3. START AND STOP
-----------------

Start:  double-click start-local.cmd in the fleetline folder.
        - "Run simulated drivers?"           Y = demo vehicles drive around the map
        - "Create a public https link?"      Y = link for your phone (needed for GPS on phones)
Stop:   close the windows whose titles start with "Fleetline".

After code changes: close all "Fleetline" windows, start the launcher again,
then press Ctrl+F5 in the browser.

Commands (in a terminal inside the backend folder):
  npm start                          start the server
  npm run simulate -- --speed 2      simulated drivers (2 = twice real speed)
  npm run seed -- --reset            WIPE all data and reload the demo data
  npm test                           run the automated tests

5. NATIVE PHONE APP (background tracking)
-----------------------------------------

Build it in the cloud with a free Expo account (expo.dev). Full steps: mobile/README.md
  cd mobile
  npm install
  npx eas-cli@latest login
  npx eas-cli@latest init
  npx eas-cli@latest build -p android --profile preview    -> installable Android APK

On the app's sign-in screen, enter your server address. For testing on your Wi-Fi,
use your computer's address, e.g. http://192.168.1.20:4000.
iPhone builds need an Apple Developer account ($99/year).


6. SETTINGS WORTH KNOWING (backend/.env)
----------------------------------------

GEOFENCE_M=90         a stop is marked "arrived" within this many metres
LATE_GRACE_MIN=10     minutes after the planned time before a stop counts as late
OFFLINE_MIN=3         minutes without GPS before a vehicle shows "No signal"
TILE_URL              map provider (default: Esri street map, free for testing)
ROUTING_URL           road routing (default: free public OSRM demo, testing only)
JWT_SECRET            login signing key; if empty, one is created in backend/data/


7. BEFORE GOING LIVE
--------------------

- Change all passwords above (see section 8).
- Host the backend online with HTTPS and permanent storage (e.g. Railway, Render).
- Use a map provider and routing service with your own account/API key.
- Set your own app ID in mobile/app.config.ts before publishing the phone app.
- Tell drivers their location is tracked only while on shift.


8. CHANGING PASSWORDS
---------------------

Your own password:
  Dispatch console  -> Setup tab -> "Your account"
  Driver web app    -> "Change password" at the bottom of the screen
  Native phone app  -> "Change password" at the bottom of the screen
  You need your current password. New passwords need at least 8 characters.

Someone else's password (admins only, e.g. a driver forgot theirs):
  Dispatch console -> Setup tab -> Drivers or Staff list -> "Reset password"

Changing or resetting a password signs that person out on every other device.
A driver who is reset while on shift stops sending GPS until they sign in again.


9. NEW DRIVERS (SIGN-UP AND APPROVAL)
-------------------------------------

Drivers can sign themselves up:
  Driver app / phone app -> "New driver? Request an account"
  They enter name, phone, licence number (optional), truck or van, username, password.
  They can't sign in until an admin approves them.

To approve (admins only):
  Dispatch console -> Team tab (a red number shows waiting sign-ups)
  -> pick the truck or van to assign -> Approve   (or Decline)

Admins can also add a driver directly: Setup tab -> Drivers -> Add driver
(with an optional licence number and vehicle).


10. DRIVER PERFORMANCE AND VEHICLE CONDITION
--------------------------------------------

Drivers see their own page: driver app -> "My stats"
  - this week vs their own 4-week average: trips, deliveries, on-time %,
    distance, hours on shift, driving hours
  - their rank among drivers who worked this week (by deliveries, then
    on-time rate, then distance)
  - deliveries per day for the last 14 days (on time vs late)
  - their current/expected route
  - their vehicle's condition: odometer, next service, last pre-trip check
  - recent trips

Admins see the same for every driver: console -> Team tab -> click a driver.
Vehicle pages: Team tab -> click a vehicle (or Vehicle tab -> "Condition & performance").

Vehicle condition is worked out from:
  - pre-trip checks drivers do at the start of each shift (tyres, brakes, lights,
    fluids, body, cargo area). A "Problem" alerts dispatch.
  - the odometer (grows with GPS distance) and the service interval
  - "Record service" on the vehicle page, which restarts the service countdown and
    clears problems reported before it.
Statuses: Good, Service soon (under 1,000 km), Needs attention (problem reported
or service overdue), Out of service (marked in maintenance).

Demo data includes 4 weeks of history so averages and rankings show real numbers.
To get it on your computer: npm run seed -- --reset   (this wipes current data)
